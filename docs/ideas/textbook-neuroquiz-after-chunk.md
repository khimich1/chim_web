# Нейроквиз после чанка учебника

**Проект:** `chim_web`  
**Дата:** 2026-07-25  
**Статус:** идея согласована → spec **implemented**: [`docs/specs/textbook-neuroquiz-after-chunk.md`](../specs/textbook-neuroquiz-after-chunk.md) · план [`tasks/textbook-neuroquiz-after-chunk.md`](../../tasks/textbook-neuroquiz-after-chunk.md)

Флаги: `NEUROQUIZ_ENABLED` (API) и `NEXT_PUBLIC_NEUROQUIZ_ENABLED` (оверлей в Next). Оба default off.

## Problem Statement

How Might We дать ученику лёгкую самопроверку при переходе к следующему чанку (до 4 MCQ по тексту), с опциональным +1 за верный ответ — без связи с «Тестами» и с возможностью пропустить?

## Recommended Direction

**Оверлей-квиз по «Далее» + гибрид C1 + прогрев G3 + лайки ученика.**

Контекст в коде: учебник ученика — `ChunkViewer` + SQLite `prepared_lectures` (`lecture`, `qa_questions` / `qa_answers`); баллы — ledger `student_activity_events` / `student_stats`; DeepSeek — существующий LLM-стек tutor. Раздел «Тесты» / `TestSession` **не** переиспользуем как сессию квиза.

### UX (ученик)

1. В чанке читает/слушает текст; в фоне (**G3**) готовится/греется кэш MCQ.
2. Жмёт **«Далее»** → полупрозрачный оверлей в фирменном стиле поверх текста.
3. Вопрос + варианты; ответ **по клику** на вариант (одна попытка в проходе).
4. После ответа (до «Далее»): можно **лайк/дизлайк** вопроса.
5. **«Далее»** в оверлее → следующий вопрос; после 4-го или **«Пропустить квиз»** → переход к следующему чанку (на **последнем** чанке темы квиз тоже показывается).
6. По уже пройденному чанку оверлей **снова предлагается**, но **баллы не начисляются**.

### Контент вопросов

- Цель: **4 MCQ** на чанк.
- База: `qa_questions` / `qa_answers`; DeepSeek генерирует дистракторы.
- 0 пар → 4 вопроса из `lecture` этого чанка; 1–3 → добить до 4 из текста; >4 → **первые 4** (мягкий гибрид).
- Вопросы всегда привязаны к тексту **текущего** чанка.

### Баллы

- **+1** только за **верный** ответ (новый `event_type` в activity ledger).
- Макс. **4** за чанк; идемпотентно: повторный/учебный проход = **0**.
- В UI ученика: только `total_points` / week (**без** отдельной метрики «нейроквиз»).
- Учитель видит вклад в общей статистике ученика (`4c`).

### Кэш и генерация

- Хранение кэша MCQ: **PostgreSQL**.
- **G3:** прогрев при открытии чанка; к «Далее» набор желательно готов.
- Ошибка генерации (**F3**): кнопка Retry + Пропустить.
- Без teacher-approve (**Q1**): trust + cache.

### Лайки (MVP = только ученик, T1)

- Лайк/дизлайк **на каждый вопрос**, только **после ответа** и **до** нажатия «Далее».
- Лайк → вопрос **закреплён** в кэше чанка.
- **Первый дизлайк** → вопрос **убирается из пула для всех** (пока дизлайк побеждает; пороги лайков vs дизлайков — later).
- Учительский превью квиза и лайки учителя — **не в MVP** (в учительском клиенте квиза нет).

### Перезапуск

- Квиз можно пройти снова (практика / повторный «Далее»).
- Зачёт баллов — **один раз за чанк** (даже если позже ответил лучше).

## Key Assumptions to Validate

- [ ] G3 успевает до «Далее» на типичном чтении (≥30–60 с); иначе нужен спиннер / путь F3
- [ ] Покрытие `qa_*` достаточное; добивка из `lecture` не плодит фактические ошибки в химии
- [ ] Один дизлайк не вычистит пул слишком агрессивно на малых классах
- [ ] +1×4 не ломает мотивацию рядом с +10 за верный шаг теста
- [ ] Повторный оверлей без баллов не провоцирует всегда Skip

## MVP Scope

**In:**

- Оверлей в учебнике ученика по «Далее» (`ChunkViewer`)
- API: получить MCQ для `(topic, chunk)`, submit ответа, like/dislike
- Postgres-кэш наборов/вопросов + G3 warm-up
- Гибрид C1 (`qa_*` + дистракторы / добивка из `lecture`)
- +1 идемпотентно за верный; Skip; Retry при сбое генерации
- Повторный показ без баллов

**Out (MVP):**

- Учительский клиент квиза / лайки учителя
- Связь с `TestSession` / разделом «Тесты»
- Жёсткий гейт без Skip
- Live-полная генерация квиза без кэша на каждый клик
- Отдельный ProgressWidget «нейроквиз»
- Пороги «N лайков vs 1 дизлайк»
- Редактор/approve вопросов учителем

## Not Doing (and Why)

- **Live-генерация полного квиза на каждый клик** — latency, стоимость DeepSeek, нестабильные формулы
- **Обязательный квиз без Skip** — противоречит «можно пропустить»
- **Teacher approve / лайки учителя в v1** — нет UI квиза у учителя; выбран T1
- **Отдельная витрина баллов нейроквиза** — достаточно общего ledger / total_points
- **Связь с «Тестами»** — другой сценарий (экзамен/практика), не мини-самопроверка учебника
- **Только статический self-check без MCQ** — нужен привычный квиз с вариантами ответа

## Open Questions (после MVP)

- Пороги: N лайков vs 1 дизлайк
- Подмешивание нескольких «хороших» наборов vs один закреплённый слот на позицию вопроса
- Нужен ли явный «Перезапустить квиз» внутри оверлея или достаточно повторного входа через «Далее»
- Инвалидация кэша при обновлении текста лекции в `prepared_lectures.db`

## Rejected / Deferred Alternatives

| Альтернатива | Почему не взяли |
|--------------|-----------------|
| A: Live DeepSeek MCQ целиком | Дорого, медленно, риск галлюцинаций |
| B/E: только offline batch без warm-up | Хуже UX первого захода; G3 ближе к «готово к Далее» |
| D: только открытые `qa_*` без вариантов | Не тот формат квиза |
| Блок квиза под текстом чанка | Выбран оверлей по «Далее» |
| +1 за любой ответ | Фарм; выбрано только за верный |
